/01 Key Terms

Token

Pieces of words or code. 1,000 tokens ≈ 750 words. Billing is strictly based on read/write counts.

TTL (Time To Live)

How long Claude keeps your prompt in fast memory (usually 5 mins). Every hit resets the timer.

Cache Write

The first time a prompt is saved. Costs a +25% premium over standard API pricing.

Cache Read

Retrieving a saved prompt on subsequent calls. Granted a 90% discount on standard rates.

Prefix Matching

The cache checks from token zero. The beginning of your prompt must remain 100% identical.

Breakpoint

A cache_control tag placed in the payload dictating exactly where to save state.

/02 Architecture Rules

> Exact Byte Match

Claude checks your prompt starting from token zero. Changing a single space or timestamp near the beginning invalidates the entire cache chain.

> Fixed Order

The API enforces strict structural hierarchy:

  1. Tools List
  2. System Prompts
  3. Messages Array
> Lookback Window

During multi-turn chat sessions, Claude looks back up to 20 text blocks to find your last saved breakpoint. Keep histories lean.

/02.5 TTL Economics & Rate Limits

Prompt caching dictates application viability through three billing tiers: standard uncached inputs (1.0x), premium cache writes, and deeply discounted cache reads (0.1x). Crucially, successfully read cache tokens are systematically excluded from Input Tokens Per Minute (ITPM) limits, acting as a native throughput multiplier for scaling enterprise applications.

> 5-Minute TTL (Default)
  • Write Premium 1.25x Base
  • Read Discount 0.10x Base
  • Target Workload Autonomous Agents
> 1-Hour TTL (Extended)
  • Write Premium 2.00x Base
  • Read Discount 0.10x Base
  • Target Workload Human-in-the-Loop
> WARNING: Structural constraints dictate that longer TTL entries (1-hour) must physically appear before shorter TTL entries (5-minute) in the prompt hierarchy.

/05 Workflow Tips

> TIP 01

Static Text First, Dynamic Last

Place tool schemas and main instructions at the top, and user messages at the end. Because Claude checks prompts from the start, changes at the bottom won't break the cache at the top.

> TIP 02

Append Updates to History

Never update system instructions during an active conversation to add timestamps. Changing the system prompt breaks the entire cache! Append new info as a message instead.

> TIP 03

Use Tool Search

Sending full definitions for dozens of tools wastes tokens. Mark extra tools as lightweight stubs with defer_loading: true and let Claude search for them.

> TIP 04

Reuse State When Summarizing

When summarizing, do not strip away system prompts. Send your request with the original history intact, and add "Please summarize our chat." You will get a 90% cache discount.

> TIP 05

TTL Selection

Use 5-minute TTL for automated loops. Switch to 1-hour extended TTL for apps where human users stop to read or think between queries.
