Optimization Tactics & Lexicon

A curated repository of practical token-saving hacks and CLI command utilization strategies sourced directly from active production environments.

(i) KNOW YOUR MODEL

Set your model and effort level before starting a task, as changing either one mid-conversation invalidates the prompt cache and increases costs.

The Claude model ecosystem is tiered by computational capability, latency, and cost to address different architectural workloads:

  • > Claude Haiku: The fastest and most cost-effective model in the lineup. It is engineered for near-instant latency, high-volume API requests, simple data classification, and lightweight agentic routing.
  • > Claude Sonnet: The optimized workhorse. It offers the best balance of speed and advanced intelligence, widely considered the default choice for software engineering, complex coding tasks, and multi-step autonomous workflows.
  • > Claude Opus: The heavyweight reasoning engine. It operates at a higher cost and lower speed but provides top-tier performance for highly complex logic, deep analytical tasks, and extended strategic planning.
  • > Claude Fable: A premium, highly specialized model tier designed for advanced narrative, nuanced behavioral emulation, and deeply complex contextual generation. Operating at the highest price point, it is reserved for extraordinary creative or specialized reasoning.

/01 CLI Command Lexicon

/clear
> Context Purge

Run this command strictly between discrete tasks to prevent prior, irrelevant context from persisting and artificially inflating your input token count.

/cost
> Spend & Token Analytics

Monitors your real-time token usage, cost, and cache hit rates for the active session. Essential for verifying that your prompt caching strategy is actually working and tracking your exact savings.

/config
> Environment Validation

Use this to lock in your preferred model and default effort level globally. Setting these parameters here prevents accidental mid-session changes that would silently destroy your entire prompt cache.

/compact
> Cache-Safe Summarization

Summarize your session before taking a break. This takes advantage of cheaper summarization read costs while the 1-hour prompt cache is still warm.

/context
> Footprint Audit

Execute in a fresh session to audit your baseline footprint. Allows you to disable unnecessary MCP servers or trim bloated instructions before generating code.

/btw
> Stateless Queries

Use this for exploratory tangents or side questions. It ensures temporary queries are not permanently embedded into your session history and continuously re-read.

/02 Advanced Optimization Tactics

  • Aggressive .claudeignore

    Place a .claudeignore file in your project root. By excluding build outputs, lock files, and massive JSON logs, you prevent the agent from burning millions of tokens when it inevitably executes a broad grep or automated file search.

  • Subdirectory CLAUDE.md Stacking

    Do not put every project rule into a massive global CLAUDE.md, as that cost is incurred on every session forever. Keep the root file small and place specific instructions in subdirectory CLAUDE.md files. Claude will only load them into context when it actually navigates into those folders.

  • Machine-Optimized Handoffs

    When hitting context limits, summarize exact goals, decisions, and code blocks needed for a future agent to read cold, eliminating the need to re-read the raw chat log.

  • Message Overwrites

    When the agent misunderstands, edit your original message instead of sending a follow-up correction. This replaces the failed attempt rather than endlessly stacking useless history in the context window.

  • Optimize File Mentions

    Include files using @-mentions in the initial request to prevent the agent from wasting a read tool call. Never @-mention the same file twice, as it redundantly duplicates the file in context.

  • Quiet Terminal Flags

    Append quiet flags to noisy commands (e.g., --reporter=dot) so massive blocks of standard output do not permanently embed themselves in the session history.

  • Effort Level Scoping

    Avoid defaulting to xhigh effort for routine tasks. Reserving higher effort only for complex architecture decisions prevents an unnecessary 1.5x to 3x token premium. Set the effort level before starting, as changing it mid-session breaks the cache.

  • Directory Launch Scoping

    Claude Code indexes the directory it is launched from. Instead of launching from the monorepo root for a targeted fix, cd into the specific module (e.g., packages/ui) and launch the agent there to strictly bound its exploration blast radius.
