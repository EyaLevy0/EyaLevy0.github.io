01 Key Terms Explained Simply

Before learning how prompt caching works, here are five essential terms every developer should know.

1. Token

A token is a piece of a word or code. For example, 1,000 tokens equal about 750 English words. Claude charges you based on the number of tokens it reads and writes.

2. TTL (Time To Live)

TTL is how long Claude keeps your saved prompt in its fast memory. Every time you send a request that uses this memory, the timer resets!

3. Cache Write

The very first time you send a long prompt, Claude has to read it and save it to memory. This initial step costs a small extra fee (+25%).

4. Cache Read

When you reuse the saved prompt in later requests, Claude reads it from memory. You get a huge 90% discount on these tokens!

5. Prefix Matching

Claude checks your prompt starting from the very first word. If the beginning of your prompt matches the saved memory exactly, the cache works.

6. Breakpoint

A special tag (cache_control) you place in your prompt to tell Claude: "Save everything up to this exact point."

02 How Claude Prompt Caching Works

When you send a prompt with system instructions, documents, or tools, Claude can remember them for future API calls. Here is how the rules work under the hood.

🎯 Exact Byte Matching

Claude checks your prompt starting from token zero. If you change even a single character, space, or JSON key near the beginning, Claude cannot use the cache and must re-read everything.

Rule: Keep the beginning of your prompt 100% identical.
🧱 Fixed Structure Order

Anthropic API processes your request in a strict hierarchy:

  1. Tools List
  2. System Instructions
  3. Messages Array

If you edit the Tools list, you reset the cache for System Instructions and Messages too!

🔍 20-Block Lookback

During multi-turn chat sessions, Claude looks back up to 20 text blocks to find your last saved breakpoint.

Tip: Keep conversations organized so your saved blocks stay within the 20-block window.

06 5 Practical Workflow Tips to Save Tokens

Follow these five practical guidelines to adapt your codebase and maximize your prompt cache hit rates.

Tip 01 Prompt Layout

Put Static Text First, Dynamic Text Last

Organize your prompts strictly from permanent to changing data. Place tool schemas and main instructions at the top, reference files in the middle, and user messages at the end. Because Claude checks prompts from the start, changes at the bottom won't break the cache at the top.

Tip 02 Message Updates

Append Updates to History Instead of Changing System Prompts

Never update system instructions during an active conversation to add timestamps or current status updates. Changing the system prompt breaks the entire cache! Instead, attach new information as a message at the end of the conversation history.

Tip 03 Tool Management

Use Tool Search for Large Tool Libraries

If your app supports dozens of tools, sending full definitions every time wastes tokens. Instead, mark extra tools as lightweight stubs with defer_loading: true and let Claude search for tool details only when needed.

Tip 04 Summarization

Reuse Conversation State When Summarizing

When a conversation gets too long and you need a summary, do not strip away system prompts and start a clean call. Send your request with the original system prompt and history intact, and add "Please summarize our chat." You will get a 90% cache discount on the history while summarizing!

Tip 05 TTL Selection

Pick the Right TTL For Your User Cadence

Use the standard 5-minute TTL for automated loops where tasks run back-to-back. Switch to the 1-hour extended TTL for apps where human users stop to read, type, or think between queries, preventing cache evictions during pauses.
